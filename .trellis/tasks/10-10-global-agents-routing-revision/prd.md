# 用户规则完整草案与路由命名修订

## Goal

对应根任务 consumer-update-agents-recheck；形成完整用户规则草案、Skill 路由与准确命名修订及迁移方案，当前仅规划，不修改产品文件。

## Requirements

- 对应根任务 `.trellis/tasks/10-10-consumer-update-agents-recheck`，覆盖其 R1–R11、O01–O26 规则复核、准确命名、所有新写/修改文档的行文规范、FastCtx 入口及中文写作 Skill 要求，不只处理最近补充项。
- 以 `design.md` 中完整候选文本修订用户规则模板，保留通用规则并明确 Skill/项目工作流的职责边界；当前候选只保存在本任务，不写入产品模板或安装副本。
- 修订 `pennix-fastctx-routing` 的实际操作触发、具体排除条件和对应界面文案；在 `pennix-workflow-routing`、`pennix-workflow-lifecycle`、`pennix-decision-grill` 及引用中消除已经证实的含糊指代，不机械替换正式名称或配置键。
- 补明 `pennix-trellis-project-update` 两种 `.new` 来源；不取消预览、冲突保护、明确来源验证或逐路径清理。
- 更新已知模板摘要、生命周期组件目录和相应验证；未知用户修改继续拒绝覆盖，配置键及接口行为不因文案改动而变更。
- `grok-search` 和 `windsurf-code-search` 的集合快照不直接改写；发现其问题回各自源码仓库，再更新组件目录的明确提交并物化快照。
- 行文规则覆盖回复、用户/项目规则、技能说明、提示词、方案、规范、任务记录及其他新写或修改的文档；允许 `skill`、`fork` 等约定俗成且含义明确的技术术语，按语义和句式检查含糊指代、职责混淆和不自然拼接，不因存在中文译法就要求替换。正式名称、标识及日志保留原文。完整英文文档保持英文，既有历史记录与原始引文不改写。
- 优先从 `Fenng/Tech-Doc-Style-Chinese` 提取事实保真、条件和风险、术语一致、具体动作及内容先于排版的原则优化原修订包，再新增 `pennix-chinese-tech-writing` 集合内适配版，固定来源提交并保留 MIT 版权许可和适配说明。
- 新 Skill 按中文技术写作场景发现，覆盖 Trellis 资产和显式保存到思源的技术知识；普通对话只采用核心原则，不默认加载全部资料。语义编辑、任务状态和思源写入各遵守原生接口，不新增 Hook、服务或自动存储行为。
- 新成员按现有集合清单和来源路径交付，复用事务安装、完整性验证及卸载。先完成原有修订及源码验证，再实现新 Skill；统一最终发布安装，不产生引用未安装 Skill 的中间落点。
- 后续批准范围需明确包含本任务当前封口版本；仅批准根任务不自动改变本任务实施权限。

## Acceptance Criteria

- [ ] O01–O26 全部可追溯；最终用户规则准确、精炼、无交叉或未定义代称，章节归属清楚。

- [ ] 提交推送与必要发布完成；本机原生重装后集合来源、用户模板摘要和有效规则核验通过，任务记录与临时产物边界干净。
