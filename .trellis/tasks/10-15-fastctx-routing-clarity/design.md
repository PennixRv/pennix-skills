# 默认路由与规则分层设计

## 核心改法

用户级常驻规则负责建立默认入口，专项 Skill 负责完整合同，跨组件 Skill 负责职责分流。将重复规则归位，比继续增加同义强制句更符合本次现场；是否有效仍由行为对照判断。

## 用户级 AGENTS 模板拟改稿

修改 `skills/pennix-component-lifecycle/templates/AGENTS.md.install` 的两条内容，其他正文沿用当前来源。

可用性长段拟替换为：

> 工具可用性以宿主声明和实际回执为准；单一调用入口未暴露工具或调用失败，不代表该工具在宿主中不可用。

该表述区分宿主整体与单一调用入口，适用于直接和嵌套工具，不依赖具体工具或编排器名称。已有接口归属条款继续负责规定入口；错误分类与失败处理由负责组件合同展开。

FastCtx 入口拟替换为：

> 普通本地读取、搜索和非交互命令默认使用 FastCtx，利用有界输出和续读机制控制上下文；范围、组件原生接口例外及不可用处理见 $pennix-fastctx-routing。

该表述说明默认选择的实际用途，不宣称所有结果都自动分页或永不截断。完整性与外层截断仍须由调用者检查。

## FastCtx Skill 拟调整结构

修改 `skills/pennix-fastctx-routing/SKILL.md`：

1. 将正向默认放到开头：普通本地读取、搜索和非交互命令默认使用 FastCtx，不要求用户点名。优先原生文件与搜索工具，利用有界返回与实际续读信息核对已读范围。
2. 明确首次读取 `AGENTS.md`、Skill、规范和 PRD 也适用；动作切换不改变该规则。
3. 紧接原生例外表，增加一个具体混合场景：读取 PRD 走 FastCtx，`task.py current` 走宿主原生入口，编辑 PRD 走 `apply_patch`。同轮调用不能相互继承例外，也不能合并成包含普通读取的宿主 shell。
4. 将现有可见性、直接与原生嵌套调用、失败分类和真实不可用后备集中为一节。`functions.exec` 的 `ALL_TOOLS` 只覆盖嵌套调用面；缺项不能推断宿主直接工具不存在。真实原生入口可用时按该入口调用。
5. 将输出预算、聚合截断、Partial、精确续读和已执行副作用集中为一节；参数 schema 单独保留，不混为错误降级条件。
6. 合并重复的组件禁用包装器说明；保留原生身份与绑定恢复路径及所有有效停止条件。

工具选择仍逐动作执行，不新增“每轮重读规则”、重复启动核验、shell 探测包装器或常驻路由器。

## 工作流路由 Skill 拟调整

修改 `skills/pennix-workflow-routing/SKILL.md` 的本地操作分流及其紧邻段落：

- 保留组件归属表及“原生接口不可模拟”的边界，将普通本地操作明确指向 FastCtx 专项合同。
- 删除与专项 Skill 重复的整段 `ALL_TOOLS`、FastCtx 错误分类、分页和编排细节，改为必要指针；专项 Skill 是这些细节的维护权威。
- 保留 Trellis 原生 shell、身份与绑定的跨组件恢复说明，避免内容去重破坏已修复的协议边界。
- 不扩展到外部检索、知识、Channel 或生命周期的全量重写。

## 风险与明确限制

规则去重可能意外删除错误语义，必须逐项核对保留合同。模板换版若未登记精确旧版，会被既有安全机制识别为漂移；必要兼容和测试与正文一同交付。

本方案改善默认定位和例外边界，不能强制模型永久遵循。回归仍出现普通读取绕路时应判失败，并基于实际轨迹重新定位；不通过再添同义警告、重装旧版本或挑选成功样本证明完成。真实压缩未发生时不声称已经覆盖压缩恢复。
