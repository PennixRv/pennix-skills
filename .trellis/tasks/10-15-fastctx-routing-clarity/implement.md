# 实施与行为验收计划

## 授权、分支与实施边界

本任务当前为 `planning`。规划文档完成后原生 `plan seal`，展示 revision；只有随后对本任务当前 revision 的明确批准，才记录原生 `plan approve` 并 `start`。计划实施分支为 `task/fastctx-routing-clarity`，基线 `main`；不提前切分支、改产品文件或创建产品测试夹具。

本轮封口的实施范围为源文件、必要测试和只读评估。系统发布、集合替换与用户级模板升级须在实际差异和候选提交可审阅后另获明确授权。主会话直接实施和验证，不派发子节点。

## 执行顺序

1. 取得实施批准并原生启动后，按 `trellis-before-dev` 读取本仓库适用规范，检查 Git 与安装来源、实际工具声明、模板完整性及连续两轮的原生宿主能力。保存当前版本和回滚提交；实质漂移先 replan。
2. 在当前已安装版本记录固定场景的前测。只读取批准的无秘密 fixture、Skill、必要规范和 CLI help；额外真实场景只放行明确的任务文档与只读 `current --json`，不创建或绑定任务。
3. 以最小差异修改模板与两份路由 Skill，集中重复条款并核对保留语义；不要因改措辞扩展其他组件合同。
4. 同步现有模板 revision、精确旧模板识别与针对性夹具/测试。用临时目录验证精确旧版升级、个人修改拒绝和失败保留原文件；复用已有原子写入测试。
5. 运行适用静态检查、中文文案检查和相关组件测试，审核完整差异。产出可审阅候选提交与待部署清单，停在未经授权的发布或用户级物化之前。
6. 部署取得单独授权后，依 `$pennix-component-lifecycle` 与系统 `$skill-installer` 的原生分工执行，核对两份 Skill、模板和已安装版本。不得手改安装树、回执、缓存或凭据。
7. 在相同实际宿主与固定输入下进行后测，逐动作复核完整轨迹，记录结果与未覆盖条件；把候选提交、安装来源、升级保护结果和去敏行为结论回传根任务。

## 固定行为场景与预算

| 场景 | 输入与方法 | 通过条件 |
| --- | --- | --- |
| E1：`S04-positive` | 使用既有采集器原有 fixture 和 prompt | 普通读取和搜索使用 FastCtx；包括首次读取所需 Skill 的实际入口 |
| E2：`S04-negative` | 使用既有 Trellis help 反例 | 保留 Trellis 原生入口；fixture 缺少真实任务入口时标 blocked，不合成协议 |
| E3：`S04-boundary` | 使用既有长文本与工具面场景 | 依据真实声明与回执处理；发生 Partial 时按实际续读参数继续 |
| E4：`C01` | 使用既有多文件、Partial、Trellis help 混合场景 | 独立动作正确分流，依赖续页顺序执行；整条混合命令逐动作检查 |
| E5：盲测首读 | 新会话只请求读取批准 fixture 中的 `AGENTS.md` 与规范索引并回答内容，不点名 FastCtx，不预先加载专项 Skill | 第一项普通文件读取即走实际可用的 FastCtx；先 shell 读取再纠正判失败 |
| E6：连续两轮切换 | 第一轮仅请求批准项目的原生 task CLI help；第二轮请求只读 `current --json` 并读取明确 PRD 与规范路径，不点名 FastCtx | 原生命令与普通读取分开；第二轮不继承整项任务的原生例外，不修改绑定或启动任务 |

E1–E4 复用 `evaluations/run_codex_cases.py --phase before|after --case ... --output-dir ...`，保持历史四十四用例不变。E5–E6 将固定 prompt 和文件白名单写入本任务研究记录，复用原生 Codex 只读轨迹采集方式；不修改既有 runner 去伪装其已支持其他 case 或跨轮会话。

每个阶段 E1–E4 四轮、E5 一轮、E6 两轮，共七轮；前后最多十四个模型轮次，不自动重试，不占用此前任务的预算台账。E6 原生连续会话能力不足时标 blocked，不能将拼接 checkpoint 当作连续两轮通过。未发生真实 Partial 的分支标未触发；参数、权限等错误不为了覆盖而向真实环境注入故障。

原始轨迹、stderr 和预算文件只存私有 `/tmp`，不写入 Git。记录实际宿主、模型、版本、固定输入、结果定位和逐动作结论；未得到模型信息则标未知，不猜测。

## 判定、回滚与交付

FastCtx 实际可用却用宿主 shell 读取普通文件、将 `ALL_TOOLS` 缺项或调用失败当缺失、丢失续读、重复具有副作用的命令、通过 FastCtx 模拟组件协议，均判失败。采集器摘要中的 `native_cli` 标签不能证明包含 `cat` 的整条混合命令合规。

源码回滚使用已记录提交；受管物化通过原生 owner 恢复已批准旧版本。自定义漂移停止相关部署，不强制覆盖。源侧静态检查通过、模板升级测试通过和实际行为验收分别记录；没有后测或存在关键 blocked 时，不报告路由复发已解决。
