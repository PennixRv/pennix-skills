# 技术设计

## 范围与目标

本任务只修改 `pennix-skills` 拥有的 Context Mode 集成 Skill、跨组件路由 Skill，以及 Windsurf 源修订后的 `collection.json` 固定来源。目标是用一个常驻默认规则引导适合的数据处理工作进入 Context Mode，并把例外限定为宿主专有接口和有实证的运行语义缺口。详细技术政策集中在集成 Skill；路由 Skill 只维护跨组件职责关系。

已有 `10-17-skill-collection-path-contract` 任务仍保持原状态和封口资料。本任务使用单独任务记录，不改写或重开该历史任务；相关源文件的改动按当前根任务批准范围逐项控制。

## 路由合同

- 对已授权的本地检索、内容派生和非交互命令，默认用 Context Mode；按实际输出、是否需要派生及是否需要后续回查选择执行工具，在执行器内计算并只返回所需结果。
- 完整读取、精确编辑依据、语义编辑、用户交互、宿主 MCP 和实时 continuation 按真实宿主接口合同完成。索引和摘要不能替代明确的全文读取要求。
- 只有当本次调用所需身份、权限、交互输入、取消或续接语义无法保留时，才使用宿主原生执行入口。该判断须有当前工具能力、源码或调用回执依据；不能因未试过、发现入口错误或一次失败而泛化。
- 本地索引是保存方式，不是验证或信任结论。Windsurf 候选可在本地处理和索引，但须保留来源及未核验标记，并在作为事实前核对当前源码。
- 各组件继续拥有协议、操作授权和状态。执行载体不接管 owner、不扩大授权；凭据仍遵守各自认证 owner 的私有接口。

不建立正向组件白名单，不新增 Hook 代理、自动采集、搜索索引服务、遥测或通用重试机制，不改 Skill 名称。

## 来源与交付

先由 `windsurf-code-search` 完成并提交来源 Skill 变更，再使用集合已有生成入口更新其固定 ref/commit 和成员。集合生成成员不得手工编辑。通过本仓库既有验证后，在 `main` 提交并推送；根任务负责正式物化和跨组件验收。
