## 路由验证场景

| 操作 | 必须明确的实际入口 |
|---|---|
| 读取文件、搜文本、普通 Git、构建或测试命令 | 当前宿主已暴露的 FastCtx 工具 |
| 创建或语义修改源码、配置和任务文档 | 宿主原生 `apply_patch` |
| Trellis 任务选择、阶段与批准状态 | Trellis `task.py` 经宿主原生命令接口调用 |
| 子节点派发和等待 | Trellis Channel 原生宿主接口 |
| 用户决策提问 | 宿主原生 `request_user_input` |
| 网页检索 | `grok-search` 等检索工具规定的入口，不经 FastCtx 启动 |
| 组件安装与用户模板物化 | `pennix-workflow-lifecycle` 和 `$skill-installer` 各自规定的步骤 |
| 普通本地操作所需 FastCtx 工具未被宿主暴露 | 当前宿主的原生本地工具；不伪造专门接口 |
| 已暴露工具返回参数结构、权限、传输或服务错误 | 保留实际错误，不改报“工具缺失”或自动转发 |

上述表格用于检查边界，不是第二套路由运行时。静态推演和参数结构验证不能证明模型实际永不误调用。
