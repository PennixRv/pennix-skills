# 组件实施计划

## 前置与分步执行

1. 原生封口并展示当前组件方案，取得本轮后续明确批准后原生 start。读取 before-dev、实际 spec、现有源码和相关测试，保护已有无关差异。
2. 建立逐成员合同核对表：问题、当前调用/权限/条件、引用来源、修改与 C1–C9 验证。先核对再改写，普通导航不写成发现。
3. 先修真实语言规则、写作入口、必要载体参考和适配来源说明，更新 template SHA 与完整旧版本允许列表。模板只在源码维护，用户安装副本稍后原生升级。
4. 按独立操作场景逐项修订 10 个本地成员，再在真实 Grok/Windsurf 来源完成另外 2 个成员的文档检查；每个成员改后回读差异，不凭字数或批量翻译判定完整。
5. 新交接 Markdown 文案中文硬切，保留原 schema、历史内容、现有准入步骤和覆盖拒绝；修改必要测试验证实际行为。
6. 检查 7 个已有界面文件，调整中文提示、长度和正确 `$skill-name` 引用；保持原字段及 policy，不给缺失成员补无必要 UI 文件。
7. 来源文档提交推送后固定 catalog ref/commit，按原 snapshot 交付方式更新两个快照，逐文件核对来源与集合差异。不要将根任务或源仓库私有状态复制进快照。

## 检查

- 系统 `skill-creator/scripts/quick_validate.py`：全 12 成员 frontmatter 和命名；另外用原生 YAML 解析核对界面和引用，不将 quick_validate 误称为行为审查。
- 写作 Skill 只读校对：仅本轮明确文档；区分错误、语境与样式，人工核对事实、风险、否定和确定程度，不新增风格 CI 门禁。
- `pennix-session-handoff` 现有完整 unittest：中文新提示词、同版重复渲染、未就绪拒绝、不同内容/旧英文拒绝且保留原文件、历史只读及原生流程边界。
- lifecycle 相关完整测试：集合 admission、真实完整旧 AGENTS 迁移、幂等、未知漂移拒绝、digest 与模板一致；不以 mock 允许任意旧文件。
- Grok/Windsurf 的相关离线测试与打包/来源核对；不发起付费在线请求。
- 根组合只读门禁；遵守项目格式，不编辑模板 hash 或 runtime pointer 模拟成功。

不写仅匹配行文的测试；新增逻辑有必要行为测试，纯措辞修改用语义与结构检查即可。检查失败后先核对完整错误与实际文件，再最小调整。

## 提交、安装与收敛

1. 审查后提交推送产品变更，固定精确提交。只按必要交付机制发布，不顺带更新 Trellis、FastCtx 或二进制包。
2. 系统 Skill 安装器用 `--method git`、固定提交和唯一 catalog 路径安装到新的同级 staging，核对 exact member set 与 seed 可执行模式。
3. 从该 staging 的当前 lifecycle 原生 `replace-staged --component pennix-skills`，再 `upgrade --component codex-agents`；执行原生 scoped verify。
4. 核对安装副本全部受管文件、用户规则与源模板一致，effective instruction source 未被非空 override 遮蔽；命令链接、私有回执只通过原生验证确认。
5. 组件执行/验证/部署记录保存结果；根只写提交和验收事实。精确清理本轮 staging、研究检出与候选，不删历史记录、未知文件或组件正常缓存。
6. 归档前检查实际 Git 差异及远端结果，组件原生归档后提交任务记录；后续只有记录变化且产品字节相同，不为记录重复重装。

## 暂停与回退

未批准当前方案时不开始以上产品动作；本轮规划阶段没有调用部署或测试写入。出现新的实质权限、运行接口、维护仓库、发布路径或验收选择时先记录并停依赖动作，按当前原生合同 replan。正常同范围文案修正不重新审批。

原生安装失败保留旧集合；未知规则漂移或 override 不覆盖。源码回退只还原本轮明确差异；旧交接英文文件继续保留但不增兼容渲染。没有回退批准也不能从私有缓存复造凭据、身份或运行态。
