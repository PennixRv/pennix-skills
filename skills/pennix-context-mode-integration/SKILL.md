# Context Mode 集成

先按 [`pennix-workflow-routing`](../pennix-workflow-routing/SKILL.md) 选择证据来源，再由 Context Mode 默认承载精确文本检索、已知路径读取、内容处理、等价非交互 CLI 和大输出分析；在执行器内完成筛选、解析、比较、计数和汇总。执行命令、处理返回数据、将内容写入索引是不同动作，分别按真实接口、用户指令和来源合同判断。CodeGraph 的结构索引、Windsurf 的语义候选与本组件的文本内容索引职责不同；本组件不自动调度其他 MCP。

## 工具面证据

核验工具可用性时分别记录宿主外层 MCP 工具面、`functions` 内嵌工具面、Context Mode server `tools/list` 和 `PreToolUse` matcher/decision 四层证据。每层只报告已声明、已发现、可调用或收到回执的事实；一层未暴露或失败时，其余层仍保持未知，不据此推断工具不存在或路由未发生。

## 调用前判定

Context Mode 默认承载授权范围内的本地数据处理，也可以调用可等价承载的真实非交互 owner 命令。已知路径、字面量或“本地工具”都不构成原生 shell 例外。它不是每个宿主工具调用的透明包装层。以下调用使用真实宿主入口：

1. **调用必须使用宿主专属协议。** 例如语义编辑 `apply_patch`、用户提问或审批、宿主提供的其他 MCP、视觉渲染和实时 continuation 必须走其真实接口；不能在执行器内模拟或转发协议。脱离协议后的普通返回资料仍可由 Context Mode 处理。
2. **本次调用确实无法保留必要运行语义。** 例如接口不能提供本次需要的身份、交互输入、取消或续接句柄。先依据当前工具声明、owner 接口或实际回执确认；工具发现错误、尚未测试或单次调用失败不能单独证明不兼容。权限拒绝必须遵守，不得换工具或语言绕过拒绝，也不得重新注入被过滤的环境变量。
3. **加载并遵守项目外指令。** 项目外 AGENTS.md、SKILL.md 及其必读引用直接原生完整读取，不先尝试 Context Mode。只在加载／遵守指令时适用，不把其他外部数据一并排除。

这些条件只限制具体调用的载体；除指令加载例外外，不形成按组件名、文件名、敏感标签、项目内外路径、副作用、Git、任务时长或候选可信度划分的通用黑名单。owner 仍规定命令语义、身份和授权；Context Mode 不增加权限，也不改变来源合同。权限拒绝不是换执行器、改 cwd 或扩权的理由。用户明确要求不留存某项内容时，只避开会留存该内容的路径。

入口和工具按实际输出、派生工作及当前工具帮助选择，不设固定命令数量门槛。短小固定回执可直接读取，也可由 Context Mode 承载；无需为了使用工具再包装它。批次工具可能自动索引输出，索引只提供回查，不代替全文或来源核验。

## 选择载体

| 操作 | 入口与边界 |
| --- | --- |
| 项目根内需要派生结果的文件处理、检索或非交互命令 | `ctx_execute`、`ctx_execute_file`；代码只返回需要的结果，保留路径与范围 |
| 本地数据的检索、计算及非交互命令 | 按输出和派生需求选择 `ctx_execute`、`ctx_execute_file` 或 `ctx_batch_execute`；owner 命令、参数、身份、权限和回执保持真实 |
| 短小固定回执、导航或状态查询 | 可直接读取，也可由 Context Mode 承载；无需分析时不强制包装 |
| 本地索引与回查 | `ctx_index`、`ctx_search`；可保留来源和未核验标记，索引命中与摘要不证明内容真实或已完整阅读 |
| 项目外 AGENTS.md、SKILL.md 及其必读引用的指令加载 | 直接宿主原生全文读取；不先尝试 `ctx_execute_file`，也不改用通用执行器或更换 cwd 绕过拒绝 |
| 项目内必须遵循的 Skill/AGENTS、交接必读视图及精确编辑依据 | 默认 Context Mode，完整取得并消费要求的原文和续页；摘要、搜索片段和索引不能替代全文。输出转成索引或被截断时，沿实际范围分页取得全文，接口无法完整返回时用宿主允许的原生读取 |
| 项目外普通数据 | 文件工具先检查项目包含关系及宿主明确 Read allow／deny；不新增权限。共享 Read Hook 的外部透传只停止无效建议，不禁止已获准数据处理，也不证明读取已获授权 |
| 宿主专属协议或本次无法等价保留运行语义的调用 | 使用能保留真实协议/语义的宿主入口；仅限该调用，不推导整类命令或组件禁用 |
| 长任务、交互和跨轮续接 | 仅当本次确需交互、宿主 continuation 或当前 Context Mode 接口不能提供所需续接语义时使用对应宿主入口；“长任务”本身不是排除条件 |
| 内容留存 | 按用户针对该内容的指令和来源 owner 合同判断；敏感标签、项目外位置、未核验状态或命令副作用本身不构成额外禁令 |

组件命令的职责和协议归 owner；Context Mode 可执行真实 owner CLI，并处理命令回执，只要本次调用所需的 cwd、身份、参数、退出码、授权、状态和来源均被保留。不能用 echo 或自造 JSON 替代 owner 调用。宿主 MCP 与 Channel continuation 等宿主专属协议仍用真实接口；身份无法核验或所需运行语义无法等价承载时，仅该次调用改走能够保留语义的入口。

Trellis Channel 的宿主 continuation 按当前项目的排他等待合同执行；等待期间不启动其他工具。普通 CLI 载体能力不授权后台化、并发相关写入或轮询代替原生等待。

## 结果与数据

- 区分进程退出、工具 envelope、业务状态、timeout、取消和部分输出；外层成功不代表命令成功。输出被截断时收窄范围，或沿原生入口的实际 offset 续读，不重复无界调用。
- 原生 MCP 在来源端使用可用过滤、范围、结果上限或获准文件输出。不要在执行器内模拟 MCP；已进入上下文的响应再复制进去不能节省已经发生的上下文成本。只有 owner 的真实等价 CLI 可以在输出进入上下文前由 Context Mode 执行。
- `ctx_batch_execute` 会索引输出；`ctx_execute`、`ctx_execute_file` 设置 `intent` 或产生超大输出时也可能索引。调用前按工具当前合同识别留存行为，并遵守用户针对该内容的明确指令和来源 owner 对认证值、输出或数据留存的具体限制；不因敏感标签或未核验状态额外建立许可层。索引项应保留可用来源与可信度信息。
- 执行器不是文件写入安全沙箱；子进程可能访问项目工作目录并产生宿主文件副作用。语义编辑、任务资产和受保护文件必须使用原生编辑或 owner 入口，不把 `ctx_execute*` 当作写入接口。
- Context Mode 的 Hook 可能阻断、询问、有限改写、注入指导或透传；Hook 指导不等于确定性接管。先核实工具发现和本次调用回执。确认 Context Mode 调用失败后，可通过真实宿主/owner 入口完成同一获授权工作；保留错误与执行状态，避免重复已执行的副作用，也不得绕过拒绝或权限过滤。
- `ctx_fetch_and_index` 会持久化网页；它不是 Grok、官方文档或其他来源合同的替代入口。网络检索仍按对应 Skill 选择来源、凭据和后备。
- 自动恢复材料属于历史证据，不覆盖当前指令、用户授权及 Trellis/Git 事实。Context Mode 不读取 Codex 独立长期 memory，也不是工作流记忆权威。
- 默认组件数据根为 `${CODEX_HOME:-$HOME/.codex}/context-mode`；显式 `CONTEXT_MODE_DIR` 须为绝对路径。不扫旧目录、不搬迁其他 owner 数据。有限字段处理不保证任意文本脱敏。
- 自动会话派生数据按最近活动保留 30 天，普通主动索引与 Codex 原始历史保留。显式清除使用 `ctx_purge`，必须声明 `confirm: true` 和 `scope: "session"` 或 `scope: "project"`；session 仅指当前核验线程。普通卸载保留数据并报告。

安装、固定版本、MCP 与六 Hook 归属由 `$pennix-component-lifecycle` 导航到独立 `pennix` 工具；不叠加 Codex plugin，不运行组件自更新。跨组件不清时用 [`pennix-workflow-routing`](../pennix-workflow-routing/SKILL.md)。
