# 按业务场景选择辅助方法

本参考用于跨方法比较和组合，不是每轮清单或安装注册表。先判断当前问题、已有证据、阶段与授权；能直接匹配就读取对应 Skill。名称来自两个集合的逻辑成员，实际加载始终使用当前宿主声明路径；缺项不猜路径、不自动安装。正文及相对引用由具体 Skill 拥有。

## 主集合

| 方法 | 采用场景与实际产物 | 相邻能力、排除与动作边界 |
| --- | --- | --- |
| pennix-workflow-routing | 跨组件职责、方法组合或阶段衔接不清；给出 owner、入口及返回位置 | 单一已知方法直接使用，不递归再路由；无 Skill 必要时直接完成 |
| pennix-agent-output-quality | 批准前方案、研究或交付的完整性和读者重点需检查；实际补全遗漏与组织表达 | 不代替语言规范、任务接受或用户批准；简单事实保持短路径 |
| pennix-chinese-tech-writing | 中文技术内容撰写、改写、校对或审阅；保留条件、术语与确定程度 | 写作结构可配 writing-shape，零散材料才用 writing-fragments；不因语言整理取得写入或知识保存权 |
| pennix-decision-grill | 存在会改变目标、风险、体验或成本的重要用户取舍；按依赖渐进取得真实答案 | 可查事实、局部实现、已定选择不再问；任务阶段及实施授权仍由项目工作流负责 |
| pennix-codegraph-integration | 已批准且索引可用项目的符号、调用、依赖、具名流程与影响；给原生结构证据并核对工作树 | 已有字面定位可精确查文本；无可用索引不自动初始化、重建；不跨工作树借索引 |
| pennix-windsurf-code-search | 业务含义及范围清楚但无有效代码锚点；发现有界语义候选后查源码 | 已有路径或符号先精确文本或 CodeGraph；自然语言本身不构成语义检索理由 |
| pennix-tavily-search | 需要一般外部公开事实或先例；检索后核验相关正文及来源 | 本地事实先查本地；官方专门资料走相应入口；不外传本地资料，失败不自动换服务商 |
| pennix-grok-search | 需要 X 来源或当前操作明确适合 Grok，或用户/既定路线选择 Grok；给相关来源证据 | 一般网页优先 Tavily；可发现不等于应调用，遵守其认证和失败合同 |
| pennix-siyuan-knowledge | 需要用户维护的知识与经验，或明确要求整理保存知识；使用原生笔记证据或授权写入 | 原始会话历史归 trellis-session-insight，正式交接归 handoff；一般网页不转思源，读取不授权保存 |
| pennix-project-agents-governance | 项目 AGENTS 内容职责、来源链、冲突或未知 writer；给权威来源与处理方向 | 不为每次开发审计 AGENTS；生成块由原生 owner 写，全局部署归 Lifecycle |
| pennix-trellis-asset-check | 已初始化项目生成资产、Skills 或迁移残留疑似不一致；只读诊断 | 不等于更新或初始化授权；源码规范审查仍在组件仓库 |
| pennix-trellis-project-update | 明确要求更新已管理项目 Trellis 资产/工作流；核对原生预览、候选和冲突 | 系统安装归 Lifecycle；未初始化不自动 init，不以 force 掩盖差异 |
| pennix-component-lifecycle | 明确要求或已批准合同包含组件发现、安装、升级、卸载、配置或核验；给原生计划和状态 | 命令缺失不自动安装；项目 init/索引/任务走组件入口；部署和修复遵守精确目标及原生事务 |
| pennix-resource-cleanup | 用户要求盘点、预览或清理工作流历史、缓存、备份等；按资源 owner 给精确范围 | 默认只读，实际删除需授权；普通任务收尾不自动清理共享数据 |
| pennix-session-handoff | 用户表达正式跨会话交接意图；由原生 owner 建包、校验或读取并保留历史 | 暂时休息、继续任务或普通收尾不触发；不替代任务完成，写入及源会话封口核对真实授权 |

## extra 方法

| 方法 | 采用场景与实际产物 | 相邻能力、排除与动作边界 |
| --- | --- | --- |
| diagnosing-bugs | 难定位缺陷或性能退化；可证伪假设、定向探针、原因及回归信号 | 简单语法解释不做诊断循环；修复按已授权合同，复发预防可用 trellis-break-loop |
| codebase-design | 具体模块接口、深模块、seam 或测试边界需要设计；比较机制不同的方案及权衡 | 有证据的子系统架构摩擦先由 improve-codebase-architecture 定位；普通改名不扩大重构 |
| prototype | 某个状态模型、逻辑或界面问题适合用可丢弃产物验证；先定判断信号再实际试验 | 已有事实能判断时不造原型；测试目录或产物写入须符合当前授权，不自动保留或部署 |
| improve-codebase-architecture | 具名子系统或变化热点存在架构摩擦；源码依据、改进候选及推荐强度 | 不从局部修复扩成全仓审计；具体接口可接 codebase-design，候选返回决策/方案，不自动实施 |
| retro | 用户希望优化方法，或实际执行摩擦值得解释；核对现有设施、原因、owner 和建议 | 一次高影响事件也可能足够；正常收尾不强制复盘，不推断上下文压力，不自动改环境 |
| teach | 明确学习目标且练习反馈有价值；聚焦讲授、检索练习与真实反馈 | 普通术语解释无需课程；可先在对话开展，持久课程才核验学习目录，不将已讲授记为已掌握 |
| wait-what | 用户对上一实际回复有理解障碍；保留事实条件重新解释疑点 | 用户只是新增需求不重述；已知疑点直接解释，不先询问是否可解释，不自动保存知识 |
| loop-me | 重复活动的输入输出、触发和协作需要梳理；形成责任、失败处理及完成信号明确的规格 | 单次工程计划沿 Trellis；已有目录优先复用，无保存请求可对话交付，不授权自动化或调度 |
| writing-fragments | 写作观察与材料零散、结构未定；保留来源和原意，区分事实与候选 | 不强制在每次写作前收集；已有授权文档复用，无持久目标先对话，不自动写知识 |
| writing-shape | 已有材料与明确读者，需要组织成草稿或文章；实际成文并建立必要概念衔接 | 原材料只读，现有素材可直接用；普通技术文档保留原生格式，不强制逐段批准或分支模式 |

## 组合、返回与授权

中文写作约束可与教学、复盘或文章组织协作，但不要求每段重复加载。素材足够就转成文；架构候选足够就返回方案，具体不确定性才用原型。质量检查用于当前交付，不启动无关审计。辅助方法的产物写回已有自然落点，任务外请求可直接在答复交付。

阶段连接见 [phase-routing.md](phase-routing.md)。方法不形成第二套任务、阶段或接受事实。用户表达业务需求即可触发适用方法，无需点名；受保护动作仍按实际意图、对象和已有授权判断。已授权合同步骤继续执行，不重复索取批准；存在真正未决取舍时仅暂停依赖动作。
