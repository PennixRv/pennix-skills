# 输出质量参考

本参考用于复杂答复、研究／决策报告、任务交付和批准前方案展示。它补充入口 Skill 的判断维度，不是每条答复都要逐项复述的模板。

## 按读者任务组织

| 场景 | 正文应保留 | 可以放到任务材料或链接的内容 |
| --- | --- | --- |
| 简单事实或状态 | 直接结论，以及影响判断的条件或证据缺口 | 无关背景、工具流水账和多级标题 |
| 进度更新 | 新事实、实际影响、当前阻塞或下一步要解决的未知 | 已经确认的完整计划和重复日志 |
| 完成或阻塞交付 | 实际结果、关键变更、适用验证、剩余限制和必要后续 | 原始日志、无关提交列表和完整过程 |
| 研究或决策报告 | 推荐、主要依据、备选、分歧、适用条件和局限 | 大型来源矩阵及不影响选择的逐项资料 |
| 操作说明 | 环境、前提、准确步骤、成功判据和失败恢复 | 与当前操作无关的概念课和假设风险 |
| 批准前方案展示 | 问题、预期结果、范围、目标与 owner、取舍、验收、发布／安装、风险、回退和停止点 | 逐文件实现细节和完整研究过程；不能只给链接 |

先回答读者当前要解决的问题，再补充足以支持结论的依据。若某项事实尚未核验，直接写出核验状态，不用更肯定的语气填补空缺。

## 详略和重点

可以用以下问题复核每一段：

- 读者是否需要这项信息才能理解当前结论？
- 这项信息是否会改变操作、取舍、风险判断或完成判定？
- 它属于正文、列表、表格还是可追溯的任务材料？
- 删除它会不会丢失条件、否定、例外、失败处理或确定程度？

复杂不等于要写长。先保留影响结论的事实和限制，再删除重复解释；不要用固定字数、固定条数或“完整模板”替代覆盖检查。

## 载体选择

| 信息关系 | 首选载体 | 复核点 |
| --- | --- | --- |
| 连续论证或一个结论的依据 | 段落 | 一段只推进一个主要信息点，条件紧跟依赖它的结论 |
| 多个并列步骤或注意事项 | 列表 | 项目层级平行，顺序表示真实顺序 |
| 候选、组件或验收的相同字段比较 | 表格 | 列确实可比较，单元格不过长，手机上仍可扫描 |
| 步骤、分支、依赖或批准路径 | Mermaid 流程图 | 分支条件真实，正文保留关键条件 |
| 消息、调用和先后顺序 | Mermaid 时序图 | 对象、方向和有条件消息准确 |
| 状态、事件和允许转换 | Mermaid 状态图 | 状态由真实 owner 定义，事件和方向没有被图形改写 |

当前工作流只把流程、时序和状态图作为默认 Mermaid 表达；甘特图因当前客户端的真实样例不正确而排除在本轮默认范围外。不要把当前样例结果扩大为宿主对全部 Mermaid 语法的支持承诺。

图表检查三件事：图是否减少了关系理解成本，图与正文是否一致，关键条件是否仍能以文字读取。渲染不确定或图过长时，减少图的范围并保留等价文字；不为图表自动安装插件或导出工具。

## 语义复核

在交付前用“通过／需修改／不适用”记录人工判断及理由，不设置未经校准的总分。至少检查：

- 结论是否直接回答当前问题；
- 需求、用户决定和实际产物是否覆盖；
- “完成”“可用”“已验证”“推荐”等断言是否有对应证据；
- 风险、限制、未运行检查和下一步是否清楚；
- 正文、表格、Mermaid、链接和任务材料是否互相一致；
- 读者是否必须打开多份材料，才能识别本次结果或批准对象；
- 是否为了显得完整而增加了重复背景、无关方案或格式。

文本复核不能证明部署、渲染、引用或实际行为；这些结论仍要回到各自的原始入口和验收证据。

## 简短对照

不充分：“全部重启好了。”

合适：“服务已完成重启，当前运行正常；客户端重连尚未验证。”

不充分：“方案已写在 design.md，是否同意封口？”

合适的方案展示应在当前答复中说明要解决的问题、预期结果、修改目标、范围边界、关键取舍、验收、发布／安装影响、风险、回退和停止点，再链接详细材料并请求用户决定。
