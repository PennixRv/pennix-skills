# Agent 输出质量

适用于日常答复、进度更新、研究或决策报告、技术文档、任务完成／阻塞交付，以及 Trellis 方案形成后请求批准前的方案展示。目标是让当前读者能够理解、判断或执行当前事项；不追求固定篇幅、标题数量或格式丰富度。

## 先判断交付需要

- 简单事实或状态：先给直接结论，再补影响判断所需的条件或证据。保持短路径，不为形式加载全部参考。
- 需要行动或决定：写清对象、动作、前提、结果、限制和下一步；把会改变决定的风险放在正文中。
- 复杂交付：先核对需求覆盖和证据，再按读者用途组织内容；研究过程和完整矩阵放在自然落点，正文保留影响结论的依据和限制。
- 批准前方案：让用户在当前答复中看见本次批准对象、范围、实际修改目标、关键取舍、验收、发布／安装影响、风险、回退和停止点；不能只给文件链接或一句“是否批准”。

## 输出前检查

按当前场景检查，不把下面的条目机械复制成每条答复的固定模板：

1. **覆盖**：问题、已确认条件、用户决定、结果和必要后续是否齐全；没有把关键条件藏在链接、图或格式中。
2. **证据**：完成、可用、已验证和推荐等表述是否有相应事实；未知、未运行、受限和待决定事项是否保留原确定程度。
3. **详略**：每一段、列表项或表格列是否帮助读者理解、判断或操作；删除没有新增信息的前言、重复结论和空泛强调。
4. **重点**：把会改变行动或决定的信息置于读者需要它的位置；背景、过程和细节服从当前用途。
5. **结构**：按信息关系选择段落、列表、表格或图；保持平行层级和可扫描的顺序。
6. **语义**：复核主语、对象、条件、否定、因果、数字和确定程度；正文与图表、链接和实际产物保持一致。

## 结构和图表

- 连续论证使用段落；平行项目使用列表；真正需要按相同字段比较时使用简短表格。
- 步骤、分支和依赖优先考虑 Mermaid 流程图；消息往返和先后顺序考虑时序图；状态、事件和允许转换考虑状态图。
- 图表只表达有助于理解的关系。一张图聚焦一个概念，标签保持简短；正文仍写出关键条件、结论和限制，不能让图成为唯一依据。
- 当前工作流采用表格以及 Mermaid 流程、时序、状态图。甘特图不作为本轮默认表达；不要由一个客户端样例推断宿主支持全部 Mermaid 语法。宿主能力不确定时保留文字说明，并按实际渲染结果表述。
- 不为短事实、单步操作或没有可视关系的内容额外绘图；不为美化引入插件、图片、导出器或外部资源。

## 边界和参考

本 Skill 只负责输出的信息覆盖、详略、重点、结构和语义复核：

- 中文语言、术语、保真和中文排版由 `$pennix-chinese-tech-writing` 负责。
- 用户取舍、方案审查、封口和实施批准由 `$pennix-decision-grill` 及当前 Trellis 原生流程负责。
- 任务状态、工具调用、安装、发布、凭据和持久化仍由各自 owner 负责。
- 不自动改写用户文件，不引入模型评审器，不把字数、标题数量、列表比例或“像不像 AI”当作质量证明。

复杂交付、研究、方案展示或需要选择图表时，读取 [输出质量参考](references/agent-output-quality.md)；简单事实不强制读取全部参考。
