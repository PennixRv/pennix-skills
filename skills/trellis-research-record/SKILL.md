# Trellis Research Record

将任务相关研究及时落地到当前 Trellis task，避免结论只留在可压缩的会话上下文。本 Skill 不创建第二份
task、会话或运行时台账。

## 何时使用

| 当前动作 | 必须动作 |
| --- | --- |
| 单次导航、无任务价值的短小观察、普通重启、压缩、等待或验收失败 | 不创建研究记录。 |
| 活动 task 的研究、审计、资料核验或候选报告产生事实、候选、不确定项或下一步决策依据 | 在扩大范围、切换无关工作或结束当前上下文前记录研究结论。 |

## 工作顺序

1. 确认当前活动 task、实际修改目标和事实源；先核验检索或 worker 结果，不能把候选直接写成事实。
2. 在当前 task 的 `research/` 或适当任务工件写入范围、问题、带 evidence locator 的已核验事实、与事实分开的候选、
   未决项和一个有界下一动作。
3. 当用户明确要求独立复核，或结论确实需要第二视角才能可靠采用时，遵循当前项目选择的 Trellis `subnode`
   procedure；主会话核验其持久化报告后，才将结论写入 task。

## 边界

- Trellis 是 task 事实源；会话摘要、context-mode 和 worker 报告只提供线索或候选。
- 本 Skill 不创建正式 handoff、不改变 task 生命周期，也不复制对话、凭据、配置正文或原始大输出。
