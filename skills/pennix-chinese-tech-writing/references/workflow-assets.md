# 工作流文档载体

新增自定义技术文档默认使用简体中文，明确语言要求除外。已有普通技术文档、历史任务、固定引用和许可不因此重写。只对本次明确内容应用写作规范，不默认遍历旧文档。

## Trellis 资产

先尊重 Trellis 的原生格式和机械惯例，包括文件名、骨架章节、frontmatter、schema、字段、状态、解析标记、托管块、示例约定和生成流程。原生模板或骨架中的英文写法按 Trellis 合同保留；不能仅凭“解析器不依赖”就翻译或删除。我们编写的自定义正文再使用中文规范，不让排版或精简改变条件、验收和状态含义。

PRD、设计、实施计划、研究、规范各按当前项目工作流保持职责；本参考不定义另一套任务结构。语义文本编辑用原生 `apply_patch`，状态与生成资产走 Trellis 原生接口。来源需要修改时回真实维护仓库，不直接修补消费者或模板摘要。

发现写作建议与原生惯例冲突，先保留原生形式，核对实际合同并记录必要结论；不把写作规范当作改变 Trellis 的授权。

### 起草前的载体核对

落笔前读取目标文件、适用的 `AGENTS.md`、项目规范、模板和生成器，先列出不可改变的文件名、标题、frontmatter、schema、字段、状态、解析标记、托管块和示例约定。先创建或保留原生固定骨架，再在允许自定义的正文区域使用约定语言；完成后复核骨架和机器可读内容，并确认修改的是实际维护来源。英文示例只有在目标合同要求时保留，不能单独作为整份资产必须使用英文的依据。

## 用户规则与 Skill

用户规则保留跨项目长期准则和必要入口；具体方法由对应 Skill 渐进披露。Skill 的 `name`、目录、字段、命令、路径、状态和接口名称保留准确标识；可读触发描述、正文及界面提示采用约定语言。

写清能力、适用条件、必要排除、操作边界和相关参考。保留原有权限、失败、停止与验证条件；精简重复说明，不用“更短”代替完整。实际维护仓库、调用接口和状态写入组件分别说明，不以集合名或宽泛代称替代。

## 思源技术笔记

新写自定义技术知识采用约定语言，保留已核验事实、用途、适用范围、来源日期或版本及限制。保留文档组织、块 ID、引用、属性、标签和用户无关修改，不把它们改成 Markdown 外观统一的副本。

写作不授予保存、导入或晋升权。目标、原生 MCP、并发核对和写后回读由 `$pennix-siyuan-memory` 负责；任务记录和正式交接仍按各自接口处理，不因文案可复用就自动保存到思源。
