# 中文技术写作

适用于新写或修改的中文技术内容，包括普通技术文档、操作说明、API 与界面文案、工作流规则、Skill、自定义 Trellis 正文和思源技术笔记。新增技术文档默认简体中文，明确语言要求除外；不因此翻译已有文档。日常回复采用核心原则，不为短回复加载全部参考。

本 Skill 只指导内容与表达。文件语义编辑仍用原生 `apply_patch`；生成资产、Trellis 状态和思源保存遵守各自接口与授权，不自动保存知识或创建项目约定。

## 优先级与保真

先遵守目标载体的原生格式和机械惯例，再改善自定义中文内容。Trellis 原生模板、骨架章节、标记和生成流程按其合同保留，不因解析器未依赖某段文字就擅自改写。依次保留事实、逻辑、条件、风险与法律含义，遵守明确语言要求和项目约定，保持术语与机器可读内容准确，再改善表达。不能为了精简、统一或更确定的语气删除高优先级信息。

- 不补造日期、数字、时限、能力、因果或结论。必要事实无法确认时标明缺口。
- 不删前置条件、适用范围、例外、否定、单位、默认值、失败处理和兼容限制。
- 不把“可能”“建议”“通常”“计划”改成确定事实。固定引用、日志和错误原文保留，修改建议另列。
- 不改代码字面量、URL、API 路径、字段、命令、配置键或其他机器可读标识。

## 先确定模式

| 模式 | 工作边界 |
| --- | --- |
| 撰写 | 确认受众、用途、事实来源与载体，再组织已核实内容 |
| 改写 | 保留原意、层级、条件与例外，说明重要语义变化和证据缺口 |
| 校对 | 仅修正约定范围内的错字、术语和排版，不擅自重组事实 |
| 审阅 | 按影响排序，引用具体问题和建议；未经授权不直接修改 |

## 核心原则

- 先写结论或用途，再给依据、限制和必要操作。一个段落发展一个主要信息点。
- 写清执行者、对象、动作和结果；条件及风险放在依赖它们的操作之前。区分人工操作与系统自动行为。
- 同一概念用同一术语。具体仓库、组件、工具和接口用准确名称，不以宽泛集合名代替。
- 自然使用中文，不堆砌黑话或无必要的中英文拼接。`Skill`、`fork`、`API` 等通行且意义明确的技术术语可以保留；英文词有多个职责含义时，写出实际含义，例如“源码维护仓库”“安装工具”或“状态写入组件”。
- 列表保持平行层级和句式；操作按实际顺序排列，不为短句拆散条件、否定和因果。
- 本集合默认保留常用中文引号“”及嵌套引号‘’；对话可自然使用“你”，操作文档按受众选择称呼。参考资料中的其他引号只是样例，不强制替换固定引用。
- 中文 Markdown 正文通常一段一行；代码、表格、引用和显式换行保留结构。排版修改只作用于可见正文，不做全局机械替换。

## 编辑与复核

先标记不可改动的事实、条件、风险、引用和机器可读内容，再修复歧义、遗漏与术语不一致，最后处理结构、语气和排版。完成后对照原文复核主语、对象、否定范围、因果和确定程度。

需要轻量校对时，从本 Skill 目录运行 `python3 scripts/lint_copy_rules.py <明确的文件路径...>`。脚本只读，确定错误、语境警告和样式建议分级输出；运行 `--help` 查看选项。只检查本次明确的文档，不递归扫描历史任务，不把示例反例或样式建议设为 CI 门禁。它不能验证事实、授权或接口正确性，任何建议都先人工判断。

来源、许可和本地适配范围见 [UPSTREAM.md](UPSTREAM.md)；不宣称文本符合 ASD-STE100，也不自动执行写入型排版脚本。
