# 渐进决策提问

帮助用户与代理在当前范围内形成可执行的共同方案。非调研任务先筛选重要取舍；有真正需要用户决定的选择时进入本 Skill，不以复杂度、未知项数量或提问次数作为标准。边界清楚的只读研究直接完成证据；研究范围或方法确有用户取舍时仍提问。

## 与项目规划入口协作

Trellis 项目由已选 workflow 和当前阶段 Skill 负责目标探索、候选构造、方案形成、整体审查、结果接受、实施授权及变化分流。当前 fork 的前三阶段分别是目标探索与需求核对、决策空间构造与归并、解决方案设计与收敛；保留的方案取舍在第三阶段解决。本 Skill 只提供被委托的重要用户选择与交互方法，将真实答复及影响写回当前任务并返回该阶段；不自行推进阶段或复制状态、schema、revision 和命令参数。按宿主声明路径加载入口，其他版本遵守其实际合同，不猜造接口。

下文的方案审查和最终复核在项目工作流内作为质量与交互方法使用，不是另一条 Trellis 规划路径。没有项目专用规划入口时，按本 Skill 的完整方法形成方案并取得适用批准。

## 筛选真正的决策

先复用当前任务、明确指令、证据与已定选择，只补会改变结论的缺口。询问会实质改变范围、体验、职责、权限/数据、部署、成本或验收、且不能由既有约定决定的用户取舍。一个重要选择就足够，不要求多个。

代理核验可查事实并处理局部、可逆、可验证的实现选择；不让用户替代源码检索，不重复问已定事项，不把实施批准伪装成设计问题。无法核实的必要事实明确记为证据缺口，仅在确需用户协助时索取最小信息。

术语或概念的不同解释会改变范围、职责、方案或验收时，先给少量具体情境，比较各解释的行为与后果，并核对当前源码或接口。可查含义由代理核验，真实语义取舍再向用户提问；结论写当前工作的自然落点，不强制建立 Glossary 或 ADR。

## 决策树逐步演进

从当前已知范围建立简要决策链，不要求一次穷举。复用本任务的 PRD、决策或研究记录：重要节点保留问题、依据、选项、推荐及理由、依赖、实际答案及影响；有争议或变化时记下重开条件。证据与局部工程选择由代理关闭，不创建第二状态机或会话配置台账。

多目标、多负责组件、显著风险或多轮访谈时，将原始目标、约束和成功信号链接到重要节点，以及对应要求与验收；在已有计划或矩阵内用简表/标识维持关系。小任务保留足够条目即可，不强制建图，也不要求每项目标都变成用户问题。阶段、任务状态和结果接受仍由当前项目工作流负责。

| 节点情况 | 下一动作 |
| --- | --- |
| 待证据：问题可描述，但必要事实未核实 | 有界查证后回到该节点 |
| 依赖阻塞：问题可描述，但前序答案或人工前置未满足 | 先处理真实前置，保留阻断关系 |
| 范围内暂不能精确表述 | 保留未知项及受影响目标，待证据或答案展开；不能当作已解决或范围外 |
| 就绪用户取舍：事实和依赖已满足 | 按下述优先级渐进提问 |
| 已决定：有真实答复或可追溯的既定规则/证据 | 保存依据、影响及重开条件 |
| 延期或明确排除 | 分别记录理由及对目标/验收的影响，不能以缺少答案代替排除 |

每轮只选依赖和所需证据已满足的未决用户选择，再按影响与阻断优先级排序。先处理会限制后续方案的边界；后序问题可能因回答新出现、改变或不再需要。

- 本轮只问主题连贯、互不影响的就绪项，数量不超过宿主工具限额，当前为 1–3；只需一问就问一问。
- 如果前序答案会改变后序选项、推荐、范围、风险、修改仓库、负责组件、验证或下一步，后序留到之后的轮次。
- 给出简洁问题、真实互斥选项、推荐和主要后果；不以凑批次、填工具槽位或一次问全为目标。

真实答复先立即写回当前任务，再核验影响、更新分支和重算下一轮。用户自定义答案按实际意图记录，不能强行归入最接近的预设项；部分回答只关闭已答节点。改口或新证据只重开受影响的决定，保留旧结论与原因；淘汰分支标明原因，不反复提问。回答到来后继续规划，不把每轮提问当成任务结束。

答复或证据也可能显露新的重要节点、解除依赖或使分支不再适用；及时更新受影响目标、要求和验收的覆盖关系，再重算就绪前沿。方案比较或验证反馈改变问题定义时，回到受影响节点，不重开无关已定事项。记录复用当前工作已有的自然落点，不另设决策库。

决策空间构造与归并按问题复杂度选择清单、表格或决策树；只有选项之间存在会改变后续分支的依赖或条件时，才需要决策树。对新机制、重大重构、跨组件边界变化或关键不确定性，该阶段可触发 prior-art review。触发后，解决方案设计与收敛在接受正式方案前核验相关流行开源实现或公开提案，并记录其适用性及采纳或排除理由；新项目和长期维护项目的大型重构尤其应检查这类参考。外部先例帮助检验候选和假设，不替代项目事实、用户决定或方案判断，也不自动变成硬性约束。

## 有界证据辅助与上下文保护

证据工作可能拉长或分散决策链时，先在当前任务保存待决定节点、缺失事实、影响和返回动作。当前机器与源码按 `$pennix-workflow-routing` 选择来源，精确文本和等价 CLI 默认由 Context Mode 承载；外部事实也按 `$pennix-workflow-routing` 选择适用来源。只取得会改变当前决定的证据，不把整条对话或无关决定外发。

独立证据有明确并行价值且具备授权时，按当前项目的 `trellis-teamwork` 合同明确问题、只读角色、边界、证据落点和接受条件。teammate 只交报告，不写源码、主任务事实或替用户决定。主代理核验后回写原决策节点；general 是协作模式，batch 必须有已验证 adapter，不能用交互式 run/spawn 冒充 batch。派发与等待遵守原生合同，不加轮询或另一套调度器。

## 原生交互与收口

直接使用当前宿主原生阻塞式 `request_user_input`，不替换为 `request_user_input_async`、代理等待器、shell/MCP 模拟或工具发现探测。不设代理等待上限，不因时间默认采用推荐；只在原生调用实际返回后继续，宿主控制其生命周期。

`request_user_input` 属于宿主原生交互，不要求出现在 MCP 或嵌套工具清单中。`functions.exec` 的 `ALL_TOOLS` 缺项只说明不能从该编排器调用，不能证明宿主直接工具不存在；不要用嵌套清单探测或判断交互工具可用性。当前宿主直接面已声明时按其原生入口和合同调用；拒绝、参数错误、取消或超时保留实际类别，不改报为工具缺失。

宿主拒绝、取消、超时或不可用不构成真实答案；保留必要未决项并停止其依赖动作，允许时用普通文本说明。可选问题空回执服从更高优先级宿主合同，不循环重问，不声称 Skill 能保证宿主无限阻塞，不发明配置键。

就绪项为空时检查：是证据与依赖尚未完成，还是当前范围的重要取舍已明确。前者继续必要且已授权的核验；后者检查方案、修改目标、负责组件、风险和验收是否冲突。空列表不等于整体方案获接受，也不遍历理论分支或扩展未来需求来延长访谈。

## 规划/实施中的额外发现

发现原始请求之外、可能影响当前任务的事实或缺口时，先核验其是否真实，再记录它与主线的关系、实际修改目标、影响、成本、证据和建议落点。向用户提供“纳入当前任务”“记录后另建任务”“当前范围已有覆盖”“明确排除”四类真实选择；不能静默丢弃，也不能把发现本身当作纳入授权。既有同任务、同修改目标且明确授权的范围可以复用，不重复提问；新增范围仍需单独判断。

纳入规划不等于实施批准。实施中的额外发现按实际影响回到最早受影响阶段；已授权范围内的局部修复直接继续，不因“新增要求”自动重做规划。旁线问题收敛后回读原始请求、主线决策和未决项，再继续主线；不能让额外发现取代主线。

## 方案审查闸门

对于需要规划的变更，在方案和任务材料形成后、整体方案展示及批准询问前，按项目当前阶段独立复核方案是否正确、可执行且可验收。独立复核不强制另派代理，也不依赖输出排版 Skill。

检查原始目标与需求覆盖、实际修改目标与 owner、现有组件合同、范围边界、关键取舍、详细有序步骤及依赖、各步骤产物与验证、发布／安装影响、风险、回退和唯一可观察停止点，并确认用户能识别本次将要批准的对象。

按问题性质处理审查结果：

1. **证据或合同问题**：事实、接口、生命周期或 owner 不一致，或方案不能满足已确定需求时，主会话直接修正、收窄或推翻受影响分支。若改变范围、owner、风险、发布路径或验收，回到方案整理。
2. **用户取舍问题**：仍需在范围、体验、风险、成本、部署或验收之间选择时，通过本 Skill 的原生渐进提问取得实际决定；答案写回任务后重新整理和审查。
3. **已知限制**：无法消除但不阻断决定的限制，记录证据、影响和回退；若影响用户能否安全决定，先请求用户取舍。
4. **审查通过**：只有没有未解决的实质矛盾、owner 缺口、关键决策缺口或验收断裂时，才能进入下一节的完整方案展示。

实质修正、推翻或用户答复后复核受影响材料；实质矛盾未解决时不请求整体批准。“通过”表示已知问题已处理或显式保留，不宣称不存在未知错误。

项目阶段编排该复核；无项目专用入口时由本 Skill 提供方法。不新增 Trellis 或 Teamwork 状态、第二套任务台账，不替代原生阶段校验。主会话按当前项目的质量检查和组件合同核验事实。

## 最终方案复核

需要规划的变更，必要选择和证据收敛后，先展示完整方案：目标与范围、修改目标和 owner、关键决定、适用的有序步骤与依赖、产物及验证、发布／安装影响、风险、恢复和可观察停止点，并链接当前材料。逐项设计问答不等于用户认可整体方案。

尚缺整体接受或实施授权时，按宿主交互合同询问相应决定。结合上下文识别明确自由文本，不要求口令；只接受方案时不推定实施授权，明确同时批准二者则保存同一实际答复并分别交原生接口记录。已有充分整体授权不重复询问。空回执、取消和推荐项不构成批准。

明确合并授权只覆盖已展示的同一方案。Trellis 项目返回 `trellis-solution-design-and-convergence`，由当前原生接口分别接受结果、记录实施授权和推进适用路线；本 Skill 保存答复，不替组件写状态。失败先核对实际结果，不盲目重做已成功的动作；实质变化回最早受影响阶段。

纯分析完成证据不要求实施批准；直接小改保留当前 taskless 合同。协作按已选 Teamwork 规则与实际授权，不因研究复杂而默认派发。

## 执行中的新选择

普通实现沿已定选择继续。出现实质未决选择时，说明问题、影响和推荐，只暂停依赖动作并记入当前任务。Trellis 项目由当前阶段核对原生事实并分流，再按需委托本 Skill 提问；不手改 `task.json` 或伪造批准。

按项目请求接入与阶段规则判断变化影响，不让用户重复裁决可查事实。已授权的局部工程选择记入 execution 自然落点后继续；目标、候选或重大合同变化回最早受影响阶段，重新核验受影响接受及授权。独立交付和终态任务的独立后续另行接入；缺少原生状态能力时报告缺口，不另建生命周期。

普通继续或充分压缩断点复用已知决定和待办，不重新全量盘点；实际新输入只更新相关节点。当前任务记录是持久依据，提示词不是强制等待、权限隔离或模型行为的确定性保证。
